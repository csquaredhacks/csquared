## 1. The one-sentence pitch

**Hallway makes sure nobody at a conference goes solo:** it turns every attendee's "what I'm working on, what I need, what I can offer" into vectors in Elasticsearch, introduces you to the five people you should actually meet, grows a live connection graph as people scan each other's QR codes, and shows organizers which rooms are filling up in real time.

## 3. Scope: what ships today vs. what we say is next

### Ships today (MVP, in priority order)
1. **Register** — name, "what I'm working on", asks, offers, tags, groups (company/community), optional fun fact, optional comfort preferences. One form, under 60 seconds.
2. **Your five** — the 5 most relevant people to meet, each with a one-line *why* and a one-line icebreaker generated by an LLM from the ES match explanation.
3. **Connect by QR** — every profile shows a QR that encodes `https://<host>/connect/<id>`. The other person scans it with their phone's normal camera app; the page creates the edge (or sends them to register first, then connects). "I already know…" name search creates an edge too.
4. **Graph** — force-directed graph of everyone, colored by group, solid edges = connected, dashed = suggested by the matcher. Click two people → shortest intro path.
5. **Rooms** — "I'm in Room X" check-in button (and a QR per room door). Emits a metric. Web shows a simple room grid with fill level; Dash0 dashboard is the organizer view.
6. **Recap** — "People you met today" + LLM-written follow-up nudges.

### Explicitly deferred (say it in the demo as roadmap)
- NFC (QR wins: zero hardware, every phone has a camera).
- Points economy / rewards redemption (see §9 for the recommendation).
- Pre-conference email outreach, LinkedIn import, resume upload, wayfinding arrows, "growing conversations" rooms.

## 4. Architecture

```
 phones (native camera app scans QR → https://<tunnel>.trycloudflare.com)
        │
        ▼
 tunnel (cloudflared Deployment, no account) ──► hallway (ONE image: FastAPI serves /api/* and the built React app at /)
                                                     │  OTLP                         │ Dash0 RUM (browser)
                                                     ▼                               ▼
                                                otel-collector ──────────────────► Dash0
                                                     ▲
 matcher (CronJob every 2 min, same image, `python -m hallway.matcher`) ──┘
        │
        ▼
 Elasticsearch (Elastic Cloud serverless trial, ELSER via semantic_text) ◄── hallway

 Kubernetes: the Radar-connected cluster/namespace ─ Radar UI + MCP in Claude Code
 GitHub repo ─ Gitar reviews every PR; CI = GitHub Actions (ruff, pytest, tsc, build, helm lint, image push)
 LLM: OpenAI (hackathon credits) for icebreakers + recap only; embeddings come from ELSER inside ES
```

**Simplicity rules (decided):** one container image, one Helm release, one Kubernetes Secret, one `make deploy`. Attendees never install anything or create an account: a QR opens a web page, one form, done. Connecting is done with the phone's built-in camera app (the QR is a plain URL), so the web app needs no camera permission, no scanner library, and works on every phone.

### Services
| Service | Tech | Responsibility |
|---|---|---|
| `hallway` (Deployment) | FastAPI + `elasticsearch` py client + `openai`, run under `opentelemetry-instrument`; serves the Vite-built React app (`react-force-graph-2d`, `qrcode.react`) from `/` via `StaticFiles` | REST API at `/api/*`, owns index mappings and all queries, serves the UI. Dash0 RUM snippet in `index.html`. |
| `matcher` (CronJob) | Same image, command `python -m hallway.matcher` | For each attendee, run the hybrid match query and upsert top-5 `suggested` edges. Emits `hallway.matcher.pairs` metric. |
| `tunnel` (Deployment) | `cloudflare/cloudflared` running `tunnel --url http://hallway:8000` | Gives a public HTTPS URL with no account, DNS, or ingress. The URL is read from the pod log. Fallback: Ingress if the cluster has one. |
| `otel-collector` | `opentelemetry-collector-contrib` Helm chart | Receives OTLP from api/matcher, exports to Dash0 with Bearer token. |

### Why Python for the API
`opentelemetry-instrument uvicorn ...` gives traces, logs, and HTTP metrics with zero code, and `elasticsearch-py` + FastAPI is the fastest path to a working hybrid query. The alternative (all-TypeScript with Next.js API routes) is one fewer language but OTel Node auto-instrumentation in Next is fiddlier under time pressure.

## 5. Data model (Elasticsearch indices)

All indices created by `api` on startup (`PUT` if missing). `inference_id` is set explicitly to the ELSER endpoint shown in the Elastic trial (`.elser-2-elastic` on serverless; verify in Kibana → Inference endpoints).

### `attendees`
```json
{
  "mappings": {
    "properties": {
      "id":        {"type": "keyword"},
      "name":      {"type": "text", "fields": {"kw": {"type": "keyword"}}},
      "email":     {"type": "keyword"},
      "working_on":{"type": "text", "copy_to": "profile_semantic"},
      "asks":      {"type": "text", "copy_to": "asks_semantic"},
      "offers":    {"type": "text", "copy_to": "offers_semantic"},
      "fun_fact":  {"type": "text"},
      "tags":      {"type": "keyword"},
      "groups":    {"type": "keyword"},
      "comfort":   {"type": "keyword"},
      "profile_semantic": {"type": "semantic_text", "inference_id": "<ELSER_ID>"},
      "asks_semantic":    {"type": "semantic_text", "inference_id": "<ELSER_ID>"},
      "offers_semantic":  {"type": "semantic_text", "inference_id": "<ELSER_ID>"},
      "created_at": {"type": "date"}
    }
  }
}
```

### `edges`
```json
{"mappings": {"properties": {
  "id": {"type": "keyword"},
  "from": {"type": "keyword"}, "to": {"type": "keyword"},
  "kind": {"type": "keyword"},
  "score": {"type": "float"},
  "reason": {"type": "text"},
  "created_at": {"type": "date"}
}}}
```
`kind` ∈ `connected` (QR scan or "I know them"), `suggested` (matcher), `group` (same group, derived, not stored). `id` = sorted pair `min:max:kind` so upserts are idempotent.

### `checkins`
```json
{"mappings": {"properties": {
  "attendee_id": {"type": "keyword"}, "room": {"type": "keyword"}, "at": {"type": "date"}
}}}
```
Current occupancy = latest check-in per attendee (terms agg on `attendee_id` with top_hits size 1, then count by room). Also emitted as an OTel gauge so Dash0 shows it without querying ES.

### `sessions` (stretch)
Talk title/abstract/room/start/end with `abstract_semantic`. Enables "find the talk about eBPF even if the title doesn't say eBPF" and "who else is going to this talk".

## 6. The matchmaking query (the creative ES part)

For attendee **A**, find people whose **offers** satisfy A's **asks**, whose **asks** A's **offers** satisfy, who work on similar things, and who share tags — but are *not* already connected and are *not* A. Combine with RRF:

```json
{
  "retriever": {
    "rrf": {
      "rank_window_size": 50,
      "rank_constant": 20,
      "retrievers": [
        {"standard": {"query": {"semantic": {"field": "offers_semantic",  "query": "<A.asks>"}}}},
        {"standard": {"query": {"semantic": {"field": "asks_semantic",    "query": "<A.offers>"}}}},
        {"standard": {"query": {"semantic": {"field": "profile_semantic", "query": "<A.working_on>"}}}},
        {"standard": {"query": {"terms": {"tags": ["<A.tags...>"]}}}}
      ]
    }
  },
  "size": 5,
  "_source": ["id","name","working_on","asks","offers","tags","groups","fun_fact"]
}
```
Exclusions (self + already-connected ids) are applied as a `bool.must_not` wrapped around each `standard` query. If the Elastic trial rejects `semantic` inside `standard`, fall back to a `match` on the `semantic_text` field, which is supported on all 9.x deployments.

The **why** line is deterministic (which retriever(s) ranked them, e.g. "They offer Kubernetes networking help; you asked for eBPF mentorship"). The **icebreaker** is one LLM call per match with a 40-word cap, cached in the edge's `reason`.

The **matcher CronJob** runs this for every attendee every 2 minutes and upserts `suggested` edges. This is what makes the graph grow on its own during the demo and gives us a non-HTTP workload for Radar and Dash0.

## 7. API surface

| Method & path | Body / params | Returns |
|---|---|---|
| `POST /api/attendees` | `{name, email?, working_on, asks, offers, tags[], groups[], fun_fact?, comfort[]}` | `{id, ...}` and sets `hallway_id` cookie |
| `GET /api/attendees/{id}` | | attendee |
| `GET /api/attendees?q=` | name search (`match` on `name`) | `[{id,name,groups}]` |
| `GET /api/matches/{id}` | | `[{attendee, why, icebreaker, score}]` (top 5) |
| `POST /api/edges` | `{from, to, kind:"connected"}` | edge |
| `GET /api/graph` | | `{nodes:[{id,name,groups}], links:[{source,target,kind}]}` |
| `GET /api/graph/path?from=&to=` | | `[id,...]` BFS over `connected` + `group` edges |
| `POST /api/checkins` | `{attendee_id, room}` | `{room, occupancy}` and records gauge |
| `GET /api/rooms` | | `[{room, occupancy, capacity}]` |
| `GET /api/recap/{id}` | | `{met:[attendee], nudges:[string]}` |
| `POST /api/chaos` | `{mode: "latency"\|"errors"\|"off"}` | current mode (demo only; guarded by `CHAOS_ENABLED=true`) |
| `GET /healthz` | | `{ok:true, es:"green"}` |

All responses are typed in `web/src/api/types.ts`, generated from the FastAPI OpenAPI schema by `make types` (`openapi-typescript`). CI runs `tsc --noEmit`, which is the CI break we will use for the Gitar demo.

## 8. Observability design (Dash0)

- **Traces:** `opentelemetry-instrument` wraps FastAPI, httpx, and the ES client. Custom spans: `match.query`, `match.icebreaker`, `graph.bfs`.
- **Logs:** Python `logging` → OTLP via the same instrumentation; every request log carries `attendee.id` as an attribute.
- **Metrics:** `hallway.room.occupancy{room}` (gauge), `hallway.edges.total{kind}` (counter), `hallway.matcher.pairs` (counter), plus auto HTTP server metrics.
- **RUM:** Dash0 web snippet in `web/index.html`; page views and `/api` fetches become client spans linked to server traces.
- **Dashboard:** "Hallway Live" — room occupancy bar chart, matches p95 latency, edges created per minute, error rate.
- **SLO:** `POST /api/matches` p95 < 800 ms, 99% success over 1 h.
- **Chaos:** `POST /api/chaos {mode:"latency"}` adds a 1.5 s `time.sleep` inside `match.query`; `errors` makes 30% of ES calls raise. On stage: flip it, open Agent0 (or Dash0 MCP in Claude Code), ask "why did matches get slow?", show it pointing at the `match.query` span, flip it off.

## 9. Points: the recommendation

The question in the plan was "what are points for, how are they used, is it a status?" Recommendation:

- **Do not build a redemption economy today.** There is nothing to redeem at a one-day hackathon demo, and leaderboards for "most scans" reward spamming QR codes.
- **If time remains, ship one number: the Bridge Score** = number of *distinct groups* you have a `connected` edge into. It rewards reaching outside your own company/community, which is the behavior the product exists for, and it is one terms aggregation on `edges` joined with `attendees.groups`.
- Show it as a small badge on the profile and a "Top bridges" list on the graph page. Frame it as status, not currency. Rewards (meet-the-speaker slots, front-row seats) are an organizer decision we mention as roadmap.

## 10. Kubernetes / Radar / Gitar / CI

- **Helm chart** `deploy/chart/hallway` with `web` Deployment+Service, `api` Deployment+Service+HPA(optional), `matcher` CronJob, Ingress (or `kubectl port-forward` if the provided cluster has no ingress), Secret `hallway-secrets` (ES URL/API key, Dash0 token, OpenAI key) created out-of-band, never committed.
- **OTel Collector** via `open-telemetry/opentelemetry-collector` Helm chart, `mode: deployment`, OTLP receiver, `otlp` exporter to Dash0 with `Authorization: Bearer ${DASH0_AUTH_TOKEN}`.
- **Radar:** `kubectl radar` locally against the provided kubeconfig; `claude mcp add --transport http radar http://localhost:9280/mcp-readonly`. Planned real investigation: `api` memory limit `64Mi` → OOMKilled → `radar diagnose deploy/api -n <ns>`.
- **Gitar:** install app on the repo first. `.gitar/rules/*.md` (verify exact path/format in Gitar → Repository configuration; if it differs, put the same text where the dashboard says). Rules: (1) every ES search must set `size` and every RRF must set `rank_window_size`; (2) every API handler must run inside a span with the attendee id attribute; (3) any change to a response model in `api/hallway/models.py` must regenerate `web/src/api/types.ts` in the same PR; (4) no secrets, tokens, or `.env` contents in the repo; (5) all timestamps are UTC ISO-8601 and session times carry a time zone. Enable auto-apply.
- **CI (GitHub Actions):** `ruff` + `pytest` for api, `tsc --noEmit` + `vite build` for web, `helm lint`. Fast (< 3 min) so Gitar's CI diagnosis loop is demoable.

## 11. Demo script (3 minutes)

0. (Before) Seeded with 60 synthetic attendees + the team. Graph page on the big screen. QR on the slide → registration form.
1. **"Everyone here, scan this."** (20 s) Audience registers from phones. Nodes appear on the graph live.
2. **"Your five."** (30 s) One teammate's phone: top-5 matches with why + icebreaker. "I asked for eBPF help; Hallway found the person who *offers* it, not just someone who mentioned eBPF."
3. **"Scan to connect."** (20 s) Two teammates scan QRs; the dashed suggested edge turns solid on screen. Click two far-apart people → intro path.
4. **"Which room is packed?"** (30 s) Check in to Room A from phones; room grid fills; switch to the Dash0 dashboard showing the same gauge. "Organizers see this without us building them anything."
5. **"Break it."** (45 s) Flip chaos latency. Ask Agent0 (or Claude Code via Dash0 MCP) "why did matches get slow?" → points at `match.query`. Then show Radar: the OOMKilled api pod from earlier and the `radar diagnose` transcript. Then show the Gitar PR where we renamed a field, CI went red, and Gitar auto-applied the type fix.
6. **"Recap."** (15 s) End-of-day recap page with follow-up nudges. "Nobody goes solo."

## 12. Risks and fallbacks

| Risk | Fallback |
|---|---|
| ELSER / `semantic_text` not available on the trial | Use OpenAI `text-embedding-3-small` via the API, store `dense_vector`, `knn` retriever inside the same RRF. Same shape, 30 min of work. Decide by 11:30. |
| Cluster has no ingress / public URL | Default is already the `cloudflared` quick-tunnel Deployment (no account needed). If trycloudflare is blocked on venue Wi-Fi, run `cloudflared tunnel --url http://localhost:8000` on a laptop over `kubectl port-forward` using a phone hotspot. |
| Audience registration overwhelms the demo | Seeded data is the floor; live registration is the bonus. Cap at `size: 5` everywhere. |
| LLM icebreakers slow or rate-limited | Icebreakers generated async by the matcher and cached in `edges.reason`; the matches endpoint never waits on OpenAI. |
| Gitar rules path wrong | Rules text lives in `docs/GITAR_RULES.md`; paste into dashboard if the file path isn't picked up. |
| Time | Priority order in §3 is the cut line. Rooms and recap are the first to drop; graph and matches never drop. |
